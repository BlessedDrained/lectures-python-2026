# Обзор ошибок в report.py

## Таблица найденных проблем

| # | Функция | Что не так | Сценарий | Серьёзность |
|---|---------|-----------|----------|-------------|
| 1 | read_orders | Генераторное выражение захватывает ссылку на файловый объект f внутри контекста `with`. При выходе из функции файл закрывается, но генератор ещё не итерирован. При первой же попытке чтения возникает ValueError: I/O operation on closed file. | Вызов build_report() -> sum(1 for _ in orders) при итерации по orders вызывает чтение закрытого файла | Падение (ValueError) |
| 2 | totals_by_user | groupby группирует только смежные элементы с одинаковым ключом. Строки заказа идут в порядке поступления (anna, bob, anna...) — пользователи перемешаны. Каждый элемент попадает в отдельную группу вместо агрегации по пользователю. | Вывод будет {'anna': 100} вместо ожидаемого {'anna': 800, 'bob': 80, 'kate': 300}. Данные об аналитике полностью неверны. | Тихо неверный результат |
| 3 | has_large_orders | Функция проверяет сумму по строке через float(o[1]), но если order_str содержит более двух запятых (например 'anna,100,50'), то parts[1] даёт только первый amount, игнорируя остальные. Кроме того, генератор `large` может исчерпаться без выдачи результата если его не потребить принудительно. При вызове из build_report после consume — пустой результат. | Если есть заказ 'ann,100' → проверяется только 100; если сумма всех заказов пользователя > threshold, но ни один заказ отдельно не превышает — функция вернёт False | Тихо неверный результат + производительность на больших файлах |
| 4 | vip_over_limit | zip(vip_users, vip_limits) обрезается до минимальной длины списков. Если в totals больше пользователей чем в vip_limits или наоборот — данные теряются. В тестовом примере kate есть в totals но лимит для неё не указан. | При входных ['anna','bob'] и [500,10] всё работает. Но при добавлении нового VIP-пользователя, превышающего лимит, он будет пропущен если его нет во втором списке. | Производительность/вероятностная ошибка |
| 5 | last_orders | readlines() загружает весь файл в память целиком перед взятием последних n строк. Для файла размером гигабайты это приведёт к OutOfMemory. | Файл orders.txt (30 МБ, ~1 млн строк) полностью читается в RAM. Потребление памяти = размер файла. | Производительность (память) |

## Ответы на вопросы из задания

**Кате лимит не указан.** Решение: считать любой положительный итог превышением лимита (так как нулевой или отсутствующий лимит означает «любое значение подходит»). Это консервативное поведение — лучше сообщить о клиенте с любым ненулевым объёмом, чем пропустить потенциального VIP. Альтернативно можно требовать явного указания лимита и игнорировать пользователей без него.
